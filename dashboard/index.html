Webhook relay · tunnels made simple

Forward webhooks to your
local server in seconds.

Portly exposes a local HTTP server through a relay and replays incoming webhooks to it — with the original status, headers and body returned to the caller. No public IP, no router config.

Read the docs Open dashboard

portly login
portly forward http://localhost:3001/webhook

⇄

Real HTTP passthrough

The local server's status code, headers and body are returned to the original caller — not just a 200 acknowledgement.

≡

Delivery history

Every authenticated webhook is stored with its headers, body, response status and duration. Browse it in the dashboard.

⌁

Built to recover

Concurrent deliveries, keepalive pings and automatic CLI reconnect after a relay restart or cold start.

⛨

Key-based routing

Relay endpoints validate your API key against the database; keys live in your OS keyring, never in plain text logs.

How it works

1Sign in with the CLI and store your API key in the OS keyring.
2Start portly forward to open a WebSocket to the relay.
3Send a webhook to the relay URL with your key as id.
4Your local server responds; the relay returns it to the caller and logs the delivery.

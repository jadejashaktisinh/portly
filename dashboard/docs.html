Portly documentation

Portly forwards incoming webhooks to a local HTTP server through a relay. The relay validates your API key, pushes the request to the CLI over a WebSocket, and returns the local server's response to the original caller.

Hosted endpoints below use https://portly-wscl.onrender.com. The CLI defaults to this host; self-hosted instances use their own URL.

Overview

Webhook / HTTP request
        │
        ▼
   Relay Server  ──(WebSocket)──▶  Portly CLI  ──(HTTP POST)──▶  Local server
        ▲                                                          │
        └──────── status, headers, body ───────────────────────────┘

Every authenticated delivery is also written to PostgreSQL and can be inspected through the API or the web dashboard.

Quick start

1. Install the CLI

Download the binary for your OS from the GitHub releases page, rename it to portly and put it on your PATH. Or build from source with cd go-cli && go build -o portly.

2. Sign in

portly login

You'll be prompted for email and password. The API key is stored in your OS keyring (Keychain on macOS, Secret Service on Linux, Credential Manager on Windows). New users can create an account in the dashboard or via POST /auth/signup.

3. Start forwarding

portly forward http://localhost:3001/webhook

The CLI connects to wss://portly-wscl.onrender.com/ws and forwards every request to your local URL as a POST.

4. Send a webhook

curl -X POST "https://portly-wscl.onrender.com/webhook?id=<your-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"event":"test","message":"hello from portly"}'

Do not override the Host header on the hosted service — Cloudflare rejects spoofed hosts. The real hostname already satisfies the relay's dotted-host requirement. Locally, use -H "Host: demo.localhost:8000".

API reference

API responses are JSON. Authenticated endpoints require Authorization: Bearer <jwt>. JWTs expire after 7 days.

MethodPathAuthDescription
POST/auth/signupNoCreate a user. Body: {email, password, slug}. Returns {token, user}.
POST/auth/loginNoAuthenticate. Body: {email, password}. Returns {token, user}.
GET/auth/meYesReturn the authenticated user's id, email, apiKey, slug and createdAt.
GET/events?limit=50&offset=0YesList deliveries, newest first. limit is capped at 100. Returns {events, total, limit, offset}.
GET/events/:idYesReturn a single delivery. 404 if it belongs to another user.
GET/healthzNoHealth check; also pings PostgreSQL.

Passwords must be at least 8 characters. Slugs are 1–40 lowercase letters, digits or hyphens. Duplicate email or slug returns 409; invalid credentials return 401.

Relay endpoints

PathDescription
/webhook?id=<api-key>Ingests a webhook. Accepts any HTTP method; the CLI replays it as POST.
/ws?id=<api-key>&localUrl=<url>WebSocket endpoint used by portly forward.

Both endpoints validate id against the database. Unknown keys receive 401 and are not logged.

Delivery log

Each entry in /events contains:

FieldDescription
requestIdUnique correlation ID shared by the relay and CLI.
method, host, slug, pathOriginal request routing information.
headers, bodyCaptured request headers and body.
statusCodeStatus returned by the local server.
durationMsTotal forwarding time in milliseconds.
errorFailure reason, if any.
createdAtTimestamp of the delivery.

Limits & behaviour

  • Request bodies larger than 1 MB are rejected with 413.
  • A webhook waits at most 30 seconds for the local server; after that the caller gets 504.
  • The CLI uses a 25 second HTTP timeout per local request and returns 502 on failure.
  • Up to 16 local requests are processed in parallel by one CLI.
  • Forwarded requests always use POST; original headers and body are preserved.
  • Hop-by-hop headers (e.g. Connection, Transfer-Encoding) are stripped from the response.
  • Host-based slug routing is scaffolded but not enforced; routing uses the id API key.
